# Offline editor bridge

The app bootstrap consumes `@aicayzer/inkkit` and bundles its JavaScript and CSS into one offline HTML file. The native app owns document identity, generation, storage, appearance, and keyboard bindings. InkKit owns editing, preservation, tables, and clipboard conversion.

The editor build copies Inkkit's license, notice and bundled dependency notices into `dist/licenses/`, together with Vite's generated notices for the host's bundled dependencies. The app build includes that directory beside `Editor/index.html` and `editor-version.json`, which records the bundled package version for diagnostic reports. Rebuild the page and notices together when updating Inkkit.

## Documents and snapshots

The bootstrap mounts InkKit with `formats: ['md', 'rtf']`; plain text stays in the native text view. `load(source, generation, documentId, format)` and `reload(source, generation, documentId, format)` pass Markdown source, or for `rtf` the JSON text of a `RichTextDocument`. A reload in a different format is sent as a load. `snapshot(expectedGeneration)` returns the complete current document with `documentId`, `generation`, `revision`, `format`, and `dirty`: Markdown carries `text`, and RTF carries `document` as JSON text. Native validation requires the field that belongs to the loaded format. Unchanged content is a successful snapshot, and native code treats it as "keep the loaded source", so an unedited RTF file is never rewritten.

RTF files are read and written natively with `InkKitRTF`: `RTFConverter.document(fromRTF:)` before loading and `RTFConverter.rtfData(from:)` on save, after the snapshot. Any `RTFConversionError` while reading keeps the file closed. `PadDocument.text` stores RTF as canonical JSON (`PadRichText`), with an empty document as empty text.

`convert(format, expectedGeneration)` wraps InkKit's `convertDocument` for switches and Save As between Markdown and RTF. It returns `{format, text | document, lost}` without changing the editor; `lost` holds InkKit's `FormatLoss` entries, which native code turns into the confirmation alert. Plain text converts natively with `RichTextDocument(plainText:)` and `plainText`. Rejections return `{snapshotError, message}`. InkKit rejections return `{snapshotError, message}` instead of escaping the native JavaScript evaluation and triggering a fatal browser error. Native readiness, composition, pending operations, stale generations, and preservation rejections stop the current operation while leaving later snapshots available. Genuine script failures disable the bridge. Native save, export, close, switching, and termination must stop when retrieval fails.

`changed` carries the `format`, the new `text` or RTF `document` JSON, document ID, and generation. Discard reports belonging to previous documents. Appearance and formatting changes do not reload source.

## Clipboard and images

Ordinary copy exports readable text and semantic HTML. `clipboard(generation)` asynchronously captures all content; await it before replacing the pasteboard. Copy as Markdown uses a fresh snapshot. `pasteAsPlainText(text)` inserts literal text.

PadPad mounts InkKit without an image adapter and preserves image syntax literally. It does not import, store, resolve, or export managed image bytes. InkKit refuses a paste or drop that would insert an image, including mixed HTML with images, inserts nothing, and reports `image-unsupported` through `events.error`; the bridge forwards it as an `editorWarning` and the native side shows the "Images aren’t supported" pill. Paste as Plain Text remains available to keep the text. InkKit does not refuse images in its Markdown source surface, which receives text only; the native TXT editor ignores graphics. Neither shows the pill.

Authored Markdown image references remain literal source. `writeClipboard` receives readable text and semantic HTML only; the native `PadClipboardContents` writer supplies those representations. Scoped requests receive `clipboardResponse` acknowledgments after a successful native write; stale requests and write failures reject the operation. TXT editing remains in the native text editor.

## Verification

Install the locked registry dependency with `pnpm install --frozen-lockfile`, then run editor type checking, consumer tests, and the offline build. Engine regression suites belong in InkKit. Native tests additionally exercise snapshot failure and clipboard interoperability. The app bundles the published package offline; it does not require a network connection at runtime.

## Modes, commands, search, and printing

Markdown Source switches InkKit's editing mode in the existing document; it does not reload source or discard history. Scoped command state controls Undo, Redo, formatting, tables, and replacement availability. The `commands` message is InkKit's `CommandState`: its `commands` hold availability (each heading level is its own format command, `heading1` to `heading6`) and its `caret` holds the active marks, block, and quote the toolbar shows. A format, table, paste, text insertion, key, replace, undo, or redo call that InkKit refuses, for any reason except `destroyed` and `internal`, returns `{commandError, message}` and the native side reports it to the person without disabling the bridge or the rest of the queued input. Edits the person makes in the page itself (typing, shortcuts, paste, drop) are reported through `editorWarning` with an error `code`, `source` (`edit` or `clipboard`), `documentId`, and `generation`. The native side rejects stale scoped messages and chooses user-facing copy from the code; diagnostic messages are not shown verbatim. Host clipboard failures retain their original request scope; other asynchronous InkKit error callbacks do not yet supply origin context. Recoverable feedback stays separate from save and file errors. A successful edit clears edit feedback, while clipboard and print warnings remain until dismissed or the document is replaced. Dismissing feedback preserves the document and returns focus to its editor. Recoverable feedback never clears a save or file error. Native key input reaches InkKit as `keyDown({key, metaKey, ctrlKey, altKey, shiftKey}, generation)`. Find and Replace searches the current editing mode: literal Markdown in source mode and readable content in formatted mode. TXT continues to use the native text editor and find bar.

The bridge holds one InkKit `findSession` for the editor's lifetime. The host's `find(query, generation, direction)` calls `session.find` with no direction for zero (an existing result stays selected) and `previous` or `next` for -1/+1, which wrap at the ends. Scoped `searchState` messages carry the session's `FindState`: `query`, `current` (one-based, or zero when the caret is elsewhere), `total`, `documentId` and `generation`. Controls show the count alone when no match is selected. InkKit refreshes the state after selection, edits, undo, mode changes and reloads, and loading a document clears the query; reloads and mode changes keep it. `replace` delegates to the session, which replaces the current result and advances to the next, passing over a match that already reads as the replacement. Native dismissal clears Find. The native bar starts as one row and reveals aligned replacement controls through a leading disclosure; opening replacement never takes focus from Find.

Links use InkKit's policy. `normalizeLink(input)` wraps `normalizeLinkAddress` for the Link field, which stays disabled until it returns an address. `linkContext` returns the selection rectangle and `CaretState.href`, so the field starts from the link at the caret. `openLink` events reach the native side only when `canOpenLink` accepts them.

RTF documents have no source mode, and their command state reports headings, quotes and code blocks as unavailable and the alignment commands as available; the Aa menu follows it. The host keymap binds underline to Mod-u in both formats.

Print first captures current source, then awaits the scoped `printableSnapshot`, for Markdown and RTF alike. Its complete HTML includes print CSS and frozen inline image assets. A separate WebKit view waits for fonts and image decoding before presenting the native print panel, including macOS PDF options. Safe fallback warnings appear in the printable content. Snapshot, asset, rendering, and stale document failures stop printing and retain writing.

## Local diagnostics

Diagnostics are off by default. The native General settings preference calls `setDiagnosticsEnabled(boolean)` for every mounted editor. Disabling it clears engine listeners and history, native history, and the retained local report. Native TXT editing records only activity categories and counts.

`diagnosticReport()` reads metadata independently of document snapshots, including during composition, pending work, or a refused edit. The native side validates schema version 1 and copies only known enums, booleans, bounded numbers, safe presentation fields, and random diagnostic IDs. It never exports source, filenames, paths, document IDs, input characters, link destinations, or arbitrary error messages. Refusals retain the structured error code and safe preservation reason.

The native report includes the app version and build, bundled editor version, and macOS version as bounded numeric components. It contains no hardware identifiers or arbitrary OS description strings. Cached reports are validated again on launch.

The native recorder keeps at most 200 activities. It retains one bounded report file for relaunch, and identifies windows with random local scopes. Report requests time out after two seconds and retain native history if the editor is unavailable. Copy Diagnostic Report explicitly puts JSON on the native pasteboard for manual sharing while recording is enabled; failed copies preserve the previous clipboard contents. Report generation does not save or rewrite the document, including unedited RTF files.
